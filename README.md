# PomodoroRelax4

Pomodoro timer with tasks, per-user settings and statistics. Blazor Server on .NET 11, ASP.NET Core Identity, EF Core on PostgreSQL or SQL Server.

## Run locally

```powershell
cd PomodoroRelax4
dotnet run
```

Set `ConnectionStrings:DefaultConnection` (in `appsettings.Development.json` or user secrets) and pick the database with `Database:Provider`:

| `Database:Provider` | Connection string example |
| --- | --- |
| `SqlServer` (default) | `Server=localhost;Database=PomodoroRelax4;Trusted_Connection=True;Encrypt=True;TrustServerCertificate=True;MultipleActiveResultSets=true` |
| `PostgreSql` | `Host=localhost;Port=5432;Database=pomodoro;Username=postgres;Password=...` |

The app creates the database and applies pending migrations on startup.

### Styles (Tailwind)

`wwwroot/css/tailwind.css` is generated by the Tailwind 3.4.17 standalone CLI from `tailwind.config.js` and `Styles/tailwind.css`, and holds only the classes the `.razor` / `.cshtml` files use. It is committed, so `dotnet run` works without the CLI. To have the build regenerate it whenever classes change, fetch the CLI once (it is pinned by version and SHA-256 and lands in the git-ignored `.tools/`):

```bash
sh tools/get-tailwind.sh
```

Commit the regenerated `tailwind.css` along with the markup. The image build always regenerates it from the sources.

### Migrations

EF Core migrations are provider-specific, so each provider has its own set: `ApplicationDbContext` owns the SQL Server ones in `Migrations/`, and `PostgresDbContext` (a subclass with the same model) owns the PostgreSQL ones in `Migrations/PostgreSql/`. After a model change, add the migration to both:

```powershell
cd PomodoroRelax4
dotnet ef migrations add <Name> --context ApplicationDbContext
dotnet ef migrations add <Name> --context PostgresDbContext --output-dir Migrations/PostgreSql --namespace PomodoroRelax4.Migrations.PostgreSql
```

Store dates as UTC (`DateTime.UtcNow`): PostgreSQL maps `DateTime` to `timestamp with time zone`, which rejects local times.

## Accounts

Public sign-up is closed. `Admin:Email` (env `Admin__Email`) names the administrator:

1. Set it and start the app. `/Account/Register` now accepts that e-mail only, and only until it has an account.
2. Register the admin account right away; after that the register page just says registration is closed.
3. Signed in as admin, open **Users** in the top bar (`/Admin/Users`) to create accounts for everyone else and hand them their password.

Users change their own password from **Settings → Change password** (`/Account/ChangePassword`). Under **Manage** on each user, the admin can set a new password (which also clears a lockout from failed sign-ins) or delete the user together with their tasks, sessions and settings. The admin account itself is managed through `Admin:Email`, not from this page. A changed, reset or deleted account's other browsers and open tabs are signed out at the next security-stamp check, within 5 minutes.

## Tasks

The list under the timer is the to-do list. Click a task to count the next pomodoros toward it. ✎ opens a task to change its title, estimated pomodoros, priority (Low, Normal, High), due date and notes. High-priority tasks get a red `!`. The due date reads "Due today", "Due tomorrow" or a weekday, and turns red as "Overdue" once it has passed. The day is the user's own day in the browser's time zone. **Hide done** keeps finished tasks out of the list; each browser remembers that choice. **Clear done** deletes them. Their pomodoros stay in Stats.

### To Do

**To Do** in the top bar (`/todo`) shows the same tasks as a plain to-do list, in the style of Microsoft To Do. Type in the box at the top and press Enter to add one, tick the circle when it's done, and open **Completed** to see or untick finished ones. The star marks a task important (High priority). Clicking a task opens its details: title, due date (with **Today** / **Tomorrow** shortcuts), the number of pomodoros it should take, notes and **Delete**. ▶ opens the timer with that task selected. Tasks with pomodoros show `🍅 done/estimated`, and a bar fills as they get done.

- **Today**: due today, plus open tasks from earlier days.
- **Important**: starred tasks.
- **Planned**: tasks with a due date, soonest first.

A task added while Today or Planned is open is due today; one added under Important is starred.

### Working through the list with the timer

- **Tasks / Today / Important** above the list under the timer show all tasks or just one of those lists. The browser remembers the choice, and a task added while a list is shown goes into it.
- When a pomodoro brings a task to its estimate, the timer asks whether it is finished. **Done ✓** marks it done; **Not yet, +1** raises the estimate by one.
- Finishing the task the timer is on, from that question or its circle, moves the timer to the next open task in the list shown, today's first.

## Stats

**Stats** shows today's pomodoros, the current streak (days in a row with at least one, still counting until today ends) with the best streak of the past year, the all-time total, and how many pomodoros done tasks took against their estimates (`1.3× estimate`). Below that:

- **Activity** for the last 7 days, 30 days or 12 months, with the change from the period before, the daily average and the best day.
- **Time of day**: the hour pomodoros were started in, over the same period.
- **Top tasks**: the five tasks with the most pomodoros in the period, and how many had no task.
- **Past year**: one square a day, darker for more pomodoros (half a year on a phone).

Days are the viewer's own, in the browser's time zone. Only completed focus sessions count; breaks show only under Recent Sessions.

## Light and dark mode

The ☀/☾ button in the top bar switches between a light and a dark theme, on the sign-in pages as well. The choice is stored in the browser (localStorage), so each device keeps its own. Until someone picks one, the operating system's setting decides. Colours come from CSS variables in `wwwroot/css/app.css`.

## Export

**Settings → Export your data** downloads the signed-in user's account name and e-mail, settings, tasks and sessions. Times are in UTC.

- `GET /export/xlsx` is an Excel workbook with Tasks, Sessions and Settings sheets, built with ClosedXML. Every value is written as plain data, so a task title that starts with `=` stays text and never becomes a formula.
- `GET /export/json` holds the same data as JSON.

Both endpoints require sign-in and only ever return the caller's own data.

### Import

**Settings → Import a file…** (`/Data/Import`) reads either export back, into the signed-in account. The account name and e-mail in the file are ignored.

- It merges and never deletes. A task that already exists (same title and creation time, to the second) is skipped. So is a session with the same type, length and start time. Importing the same file twice, or the Excel and the JSON of one export, adds nothing the second time.
- Timer settings are replaced by the file's, clamped to the Settings page limits.
- Sessions link to their task through the `Id` / `Task id` columns, or the JSON ids. In an Excel file without those columns they fall back to matching the task title.
- Unusable rows are counted and left out: no title, zero length, or dates before 2000 or in the future.
- Files are limited to 5 MB, 10,000 tasks and 200,000 sessions. An `.xlsx` that would unpack to more than 50 MB is refused before it is opened.
- Everything is written in one transaction. The Excel column headers are what the import reads, so rename them in `ExportService` and `ImportService` together.

## Security

- Passwords need at least 12 characters (`Services/PasswordRules.cs`).
- Sign-in is limited to 10 attempts per 15 minutes per client IP, and the admin-only register form to 5 per hour. An account locks for 15 minutes after 20 failed attempts in a row; that limit is a backstop for guesses spread over many IPs, and is set high so a single IP can't lock someone out quickly. A successful sign-in resets the count.
- In Production the sign-in cookie is always `Secure`, plain HTTP is redirected to HTTPS (308, except `/healthz`) and HSTS is on.
- Every response carries a Content-Security-Policy with `script-src 'self'`, plus `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` and `Referrer-Policy`. So scripts live in `wwwroot/js`, never inline (`<form data-confirm="...">` replaces `onsubmit="confirm(...)"`). Styles and fonts are served from the app as well (Tailwind is compiled at build time, Inter and JetBrains Mono are in `wwwroot/fonts`), so the policy allows no third-party origin and pages make no requests to Google.
- Signing out is an antiforgery-checked POST; a GET to `/Account/Logout` only goes home.
- The workflow's actions are pinned to commit SHAs. `.github/dependabot.yml` opens weekly PRs for them and for NuGet packages, including the `System.Security.Cryptography.Pkcs` pin in the csproj that lifts a vulnerable transitive version from SqlClient.

The `Admin` role always follows the configured e-mail: on startup it is given to that account and taken from any other, so changing `Admin:Email` and restarting moves it (the old admin sees the change at their next sign-in).

## Deploy (Podman)

`Containerfile` builds one image for the app. `deploy/quadlet` runs it as systemd services next to PostgreSQL 18: a shared `pomodoro` network, a `pomodoro-db` volume for the database and a `pomodoro-keys` volume for ASP.NET Core Data Protection keys. Keep that second volume: losing it signs everyone out. The app applies migrations itself on startup; the database unit reports ready only once it accepts connections, and the app unit restarts if a migration still fails. Quadlet needs Podman 5.0 or newer.

To run on SQL Server 2022 (Express edition) instead, copy `deploy/quadlet/sqlserver/*` over the PostgreSQL `pomodoro-db.container` and use the SQL Server block of the env file. Its data goes to a `pomodoro-mssql` volume, and the image needs an x86-64 host with about 2 GB of RAM. Switching provider starts from an empty database; nothing is copied across.

Every push to `main` runs `.github/workflows/container.yml`, which builds the `Containerfile` and pushes `ghcr.io/anilkay/pomodororelax4` tagged `latest` and with the full commit SHA. The package is public, so the server pulls it without logging in.

```bash
# Rootless (the user needs lingering so services survive logout):
mkdir -p ~/.config/pomodoro ~/.config/containers/systemd
cp deploy/pomodoro.env.example ~/.config/pomodoro/pomodoro.env   # set the DB password twice and Admin__Email
chmod 600 ~/.config/pomodoro/pomodoro.env
cp deploy/quadlet/pomodoro* ~/.config/containers/systemd/   # skip pomodoro-tunnel.container until tunnel.env exists
# SQL Server instead: cp deploy/quadlet/sqlserver/* ~/.config/containers/systemd/
loginctl enable-linger "$USER"
systemctl --user daemon-reload
systemctl --user start pomodoro-app
journalctl --user -u pomodoro-app -f
```

Then register the admin e-mail on `/Account/Register` before anyone else can (see [Accounts](#accounts)).

For a rootful install use `/etc/pomodoro/pomodoro.env`, `/etc/containers/systemd/` and `systemctl` without `--user`; the units find the env file through `%E` in both cases.

The app unit carries `AutoUpdate=registry`. `podman auto-update` (or enabling `podman-auto-update.timer`) pulls a newer `latest` and restarts the app, which applies any new migrations as it starts. To pin a release, replace `latest` with a `sha-<commit>` tag. To run a locally built image instead, `podman build -t localhost/pomodororelax4:latest -f Containerfile .` and point `Image=` at it.

The app listens on `127.0.0.1:8082` over plain HTTP. Put a TLS-terminating proxy in front of it (Cloudflare Tunnel below, or Caddy/nginx); `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` in the env file makes the app trust its `X-Forwarded-*` headers, so it knows the request came over HTTPS and the sign-in and register rate limits see the real client address. Keep it on: without it every request looks like plain HTTP and the HTTPS redirect loops. Also turn on **SSL/TLS → Edge Certificates → Always Use HTTPS** in Cloudflare, so a password typed on an `http://` URL never leaves the browser unencrypted.

`GET /healthz` returns `Healthy` (200) when the app can reach its database and `Unhealthy` (503) otherwise. Point an uptime monitor at it.

### Cloudflare Tunnel

`pomodoro-tunnel` runs `cloudflared` on the `pomodoro` network and opens an outbound-only connection to Cloudflare, which serves the site over HTTPS on your own domain. No inbound port is needed on the server.

1. In Cloudflare **Zero Trust > Networks > Tunnels**, create a tunnel (type *Cloudflared*) and copy the token from the install command.
2. Under the tunnel's **Public Hostname** tab, add your hostname (for example `pomodoro.example.com`) with service type `HTTP` and URL `pomodoro-app:8080`. The domain's DNS must be on Cloudflare.
3. On the server:

```bash
cp deploy/tunnel.env.example ~/.config/pomodoro/tunnel.env   # set TUNNEL_TOKEN, no quotes
chmod 600 ~/.config/pomodoro/tunnel.env
cp deploy/quadlet/pomodoro-tunnel.container ~/.config/containers/systemd/
systemctl --user daemon-reload
systemctl --user start pomodoro-tunnel
journalctl --user -u pomodoro-tunnel -f   # wait for "Registered tunnel connection"
```

Blazor Server keeps a WebSocket open per browser tab; Cloudflare Tunnel passes WebSockets through without extra settings. If you use nginx instead, forward the `Upgrade` and `Connection` headers.

### Compose

`deploy/compose.yaml` describes the same stack for `podman compose -f deploy/compose.yaml up -d --build` (with the env file at `deploy/pomodoro.env`), which is handy for trying the image locally; `deploy/compose.sqlserver.yaml` is the SQL Server variant. Add `--profile tunnel` and `deploy/tunnel.env` to start the tunnel too.

### Backups

PostgreSQL (`pomodoro-db` volume):

```bash
podman exec pomodoro-db pg_dump -U pomodoro -Fc pomodoro > pomodoro.dump
# restore: podman exec -i pomodoro-db pg_restore -U pomodoro -d pomodoro --clean < pomodoro.dump
```

SQL Server (`pomodoro-mssql` volume):

```bash
podman exec pomodoro-db /opt/mssql-tools18/bin/sqlcmd -C -S localhost -U sa -P '<password>' \
  -Q "BACKUP DATABASE PomodoroRelax4 TO DISK='/var/opt/mssql/data/pomodoro.bak' WITH INIT"
podman cp pomodoro-db:/var/opt/mssql/data/pomodoro.bak .
```
